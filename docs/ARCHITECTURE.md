# Architecture

Bilingual Manga Reader and Mokuro Converter shares one Python/SQLite/vanilla-web core on macOS and Windows. The native launcher starts a loopback-only HTTP service and opens the ordinary installed Chrome profile, preserving Yomitan and the user's existing dictionaries and Anki setup. Static UI files are bundled; ordinary reading has no remote dependency.

The server binds only to `127.0.0.1`, validates same-origin requests, and never exposes manga to the LAN. The database stores stable page identities, volume metadata, progress, favorites, bookmarks, settings, and normalized many-to-many page mappings. Images remain filesystem files and cached thumbnails prevent full pages from being decoded in library views.

Single import uses a native macOS or Windows picker. Bulk add uses a native parent-folder picker and an asynchronous read-only recursive scan. Mokuro sidecars, image folders, PDF, CBZ/ZIP, and TAR files become separate review items. Unicode paths are supported. Archives have path-traversal, special-entry, member-count, and expansion-size checks; per-item transactions ensure one damaged archive does not stop a collection.

Metadata comes from Bilingual Manga archive IDs, `.mokuro` metadata, and conservative filename inference. The [Bilingual Manga archive](https://github.com/B-M-dev/Bilingual-Manga-archive) is linked wherever its data is discussed. Because the upstream repository provides no redistribution license, its dataset is not copied into release packages; a fresh install instead caches and validates recognition metadata from that linked source on first use. The generic mapping importer and local catalogue format remain available for licensed exports.

Opposite-language editions first use exact series/volume matches. Fuzzy title, volume/chapter number, and page-count evidence can identify an unambiguous match; ambiguous candidates require a user choice. Pages are aligned by direct mappings, structural offset detection, then monotonic visual sequence alignment. Mappings support unmatched pages and grouped 1↔2 or 2↔1 spreads. Low-confidence results stay behind review gating, and manual anchors remain authoritative.

Raw Japanese editions run through a serialized background Mokuro queue. Referenced pages are copied into a readable app-managed folder before conversion; already managed pages convert in place without a redundant full copy. Output is adopted only after `.mokuro` page-count validation. PDF is rendered locally into pages before the same process. The pinned converter environment and model cache live in user data, not the app bundle. A bundled `uv` bootstrapper supplies private Python on clean systems; no developer runtime is required. Hardware acceleration is left enabled so Mokuro/PyTorch can select Apple GPU or other supported acceleration automatically.

macOS data lives at `~/Library/Application Support/Bilingual Manga Reader and Mokuro Converter`; Windows data lives at `%APPDATA%\Bilingual Manga Reader and Mokuro Converter`. Both old product folders migrate without losing the database or managed files. The default reader address is `127.0.0.1:48765`, with a free-port fallback, and sleeping tabs reconnect when the local service returns. Port `8765` is intentionally left available for AnkiConnect. Every request must come from loopback with a local Host and same-origin browser context; foreign Host, Origin, and cross-site fetch metadata are rejected. Browser hardening headers prevent framing, base-URL rewriting, plugin objects, camera, microphone, and geolocation access while preserving Yomitan injection.

External originals are preserved by default. A user-selected delete option first verifies a managed import or completed conversion, then moves the exact source to Trash/Recycle Bin. Broad paths and app-managed directories are refused. Library removal is transactional and deletes only unshared managed roots; external removal remains explicit and recoverable.
